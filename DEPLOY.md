# Deploying Connect.Two

The app is **two deployables** because the backend needs a long-running process
(Socket.IO WebSocket signaling + MongoDB change streams), which serverless
platforms like Vercel can't host:

| Piece | Host | Config |
| ----- | ---- | ------ |
| React client (`client/`) | **Vercel** | `client/vercel.json` |
| Express + Socket.IO backend | **Render** | `render.yaml` |

Deploy the **backend first** (the client needs its URL), then wire the two
together. Follow the steps in order.

---

## 1. Backend → Render

1. Push this repo to GitHub (already done).
2. Render Dashboard → **New → Blueprint** → select this repo. Render reads
   `render.yaml` and creates the `connecttwo-backend` web service.
3. Set the secret env vars (Render marks them `sync:false`, so they're **not**
   in git — copy the real values from your local `.env`):
   - `GOOGLE_CLIENT_ID`
   - `MONGODB_URI` (your MongoDB Atlas connection string)
   - `ASSEMBLYAI_API_KEY`
   - `GOOGLE_API_KEY`
   - `GEMINI_MODEL` (optional; defaults to `gemini-2.5-flash`)
   - `CLIENT_ORIGIN` → leave as a placeholder for now (e.g. `https://example.com`);
     you'll set it to the real Vercel URL in step 3.
   - `JWT_SECRET` is auto-generated by Render — leave it.
4. **MongoDB Atlas network access:** add `0.0.0.0/0` (or Render's egress IPs) to
   the Atlas IP allowlist, or the backend can't reach the DB.
5. Deploy. Copy the service URL, e.g. `https://connecttwo-backend.onrender.com`.

> Free Render web services **spin down after ~15 min idle**; the first request
> then takes ~50s to cold-start. Fine for a demo; upgrade the plan for always-on.

## 2. Client → Vercel

1. Vercel → **Add New → Project** → import this repo.
2. **Root Directory: `client`** (important — the app lives in the subfolder).
   Vercel auto-detects Create React App from `client/vercel.json`.
3. Add Environment Variables (Production):
   - `REACT_APP_API_URL` = your Render backend URL from step 1
     (e.g. `https://connecttwo-backend.onrender.com`)
   - `REACT_APP_GOOGLE_CLIENT_ID` = same Google client ID as the backend
   - `REACT_APP_TRANSCRIPTION_MODE` = `assemblyai` (or `webspeech`)
4. Deploy. Copy the resulting URL, e.g. `https://connect-two.vercel.app`.

## 3. Wire them together (CORS + OAuth)

1. **Render:** set `CLIENT_ORIGIN` to the exact Vercel URL from step 2
   (no trailing slash), then redeploy. This lets the browser's credentialed
   requests and the Socket.IO handshake pass the CORS check.
   - Add the Vercel preview domain too if you want PR previews to work:
     `https://connect-two.vercel.app,https://connect-two-git-*.vercel.app`
2. **Google Cloud Console** → APIs & Services → Credentials → your OAuth client:
   - **Authorized JavaScript origins:** add the Vercel URL
     (`https://connect-two.vercel.app`).
   - Save (Google changes can take a few minutes to propagate).

## 4. Verify

- Open the Vercel URL, sign in with Google.
- Start a call in two tabs/devices → video + signaling should connect.
- End a call → transcript persists and a summary appears (confirms Mongo +
  change stream + Gemini are all reachable from Render).

---

### Env var summary

**Backend (Render):** `NODE_ENV`, `JWT_SECRET` (auto), `GOOGLE_CLIENT_ID`,
`MONGODB_URI`, `ASSEMBLYAI_API_KEY`, `GOOGLE_API_KEY`, `GEMINI_MODEL` (opt),
`CLIENT_ORIGIN`, `PORT` (auto-injected by Render).

**Client (Vercel):** `REACT_APP_API_URL`, `REACT_APP_GOOGLE_CLIENT_ID`,
`REACT_APP_TRANSCRIPTION_MODE`.
